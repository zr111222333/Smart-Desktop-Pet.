# Smart-Desktop-Pet

## 项目简介

基于 STM32F103 搭建的五舵机智能桌宠系统。

项目通过离线语音模块和蓝牙实现双通道指令控制，结合 5 路舵机完成站立、坐下、趴下、前进、后退、转向、摇摆、摇尾巴等动作，同时使用 OLED 显示表情及电池电压，并通过 PWM 实现呼吸灯效果。

软件上采用“命令接收 → 动作分发 → 目标角度生成 → 周期平滑更新 → PWM 输出”的分层控制方式，将具体动作与底层舵机控制解耦，并针对舵机动作生硬的问题实现基于目标角度误差的比例缓动和步长限幅。

> 本项目硬件方案基于开源项目，个人主要完成元件焊接、模块接线、整机联调以及 STM32 端软件实现。

---

## 主要功能

- STM32F103 主控
- 5 路舵机协同控制
- 50 Hz 舵机 PWM 输出
- 舵机目标角度 / 当前角度分离
- 20 ms 周期舵机平滑轨迹更新
- 舵机角度偏置、镜像及机械限幅
- SU-03T 离线语音控制
- 蓝牙串口控制
- USART1 / USART3 双串口中断接收
- 统一命令解析与动作分发
- OLED 表情显示
- ADC + DMA 电池电压采集
- 一阶低通滤波降低电压显示抖动
- 双路 PWM 呼吸灯控制

## 系统控制流程

整体控制链路：

语音模块 / 蓝牙
        ↓
USART1 / USART3 接收中断
        ↓
RxData + RxFlag
        ↓
统一记录控制命令
        ↓
PetAction 动作解析
        ↓
Action 动作关键帧
        ↓
设置 5 路舵机目标角度
        ↓
TIM4 每 20 ms 周期更新
        ↓
Servo 平滑轨迹计算
        ↓
当前角度逐步逼近目标角度
        ↓
PWM 更新
        ↓
5 路舵机执行动作

OLED、呼吸灯以及 ADC 电池采样作为独立功能模块与运动控制协同运行。

## 1. 系统初始化

系统启动后主要完成以下模块初始化：

- TIM4 周期任务
- OLED 显示
- ADC + DMA 电压采集
- 动作控制模块
- USART1 离线语音通信
- USART3 蓝牙通信
- 5 路舵机 PWM
- 呼吸灯 PWM

初始化完成后进入主循环，由 `PetAction_SelectAction()` 负责处理已经接收到的控制命令。

---

## 2. 双串口指令接收

系统具有两种控制方式：

### 离线语音控制

SU-03T 离线语音模块通过 USART1 与 STM32 通信。

串口接收到一个动作命令后：

1. USART1 产生 RXNE 接收中断；
2. 中断中读取接收到的单字节数据；
3. 保存到 `Serial_RxData`；
4. 设置 `Serial_RxFlag`；
5. 退出中断，不直接执行复杂动作。

### 蓝牙控制

蓝牙模块通过 USART3 接收手机发送的控制指令。

处理方式与语音模块类似：

1. USART3 接收中断；
2. 保存接收数据；
3. 设置接收完成标志；
4. 后续统一交给动作模块处理。

这种方式使串口中断只负责“接收数据”，避免直接在中断中执行复杂动作导致长时间阻塞。

---

## 3. 统一命令分发

语音模块和蓝牙虽然使用不同串口，但最终使用同一套动作命令。

TIM4 周期任务调用：

`PetAction_RecordCommand()`

分别检查：

- USART1 语音命令
- USART3 蓝牙命令

检测到新命令后，将其统一写入：

`PetAction_ActionState`

主循环中的：

`PetAction_SelectAction()`

再根据命令码执行对应动作。

因此整个通信结构可以概括为：

语音 / 蓝牙
→ 不同 UART 接收
→ 统一命令
→ 统一动作接口

上层动作模块不需要关心命令来自语音还是蓝牙。

---

## 4. 动作控制

桌宠动作由 `Action.c` 负责组织。

当前支持的动作包括：

- 站立
- 坐下
- 趴下
- 前进
- 后退
- 左转
- 右转
- 摇摆
- 快速移动
- 打招呼
- 伸展
- 摇尾巴

每个动作本质上由若干组舵机目标角度组成。

Action 层并不直接修改 PWM，而是只负责设置：

`Servo_TargetAngle[]`

即：

动作指令
→ 动作关键帧
→ 5 路目标角度

具体舵机如何运动到目标位置，则由 Servo 层统一处理。

---

## 5. 舵机平滑运动

项目中将：

- `Servo_TargetAngle[]`：目标角度
- `Servo_CurrtntAngle[]`：当前角度

分别保存。

Action 层只修改目标角度，TIM4 每 20 ms 调用一次舵机更新函数，使当前角度逐步逼近目标角度。

基本控制逻辑：

error = TargetAngle - CurrentAngle

step = |error| × K

然后对单周期步长进行限制：

- 最小步长：0.5°
- 最大步长：3°

最终：

CurrentAngle += step

当目标角度较远时，舵机以较大的步长快速运动；

当接近目标角度时，步长随误差逐渐减小；

当角度误差小于 0.5° 时直接认为到达目标位置。

这种方式相比直接将舵机从当前角度跳变到目标角度，可以降低动作突变，使多舵机组合动作更加平滑。

当前比例系数默认：

`K = 0.3`

需要说明的是，该方法属于比例缓动 + 步长限幅，并不是严格意义上的 S 曲线轨迹规划。

---

## 6. 舵机 PWM 输出

5 路舵机分别使用：

- TIM2 CH1 ~ CH4：四路腿部舵机
- TIM3 CH1：尾部舵机

PWM 周期：

20 ms

对应频率：

50 Hz

角度范围：

0° ~ 180°

PWM 高电平脉宽约为：

0.5 ms ~ 2.5 ms

程序将目标角度转换为对应的 CCR 值，并写入定时器比较寄存器。

PWM 使用预装载功能，新 CCR 值在下一个 PWM 周期更新，避免在当前周期中途修改比较值造成输出异常。

同时针对不同舵机加入：

- 安装方向镜像
- 零位偏置
- 角度限幅

用于补偿机械安装误差并避免超过实际运动范围。

---

## 7. OLED 表情显示

使用 128 × 64 OLED 作为桌宠显示界面，通过软件 I2C 与 STM32 通信。

不同动作可以对应不同表情，例如：

- 开心
- 睡觉
- 打招呼
- 注视
- 兴奋

动作执行时由 `PetAction` 同时调用：

动作函数 + 表情显示函数

从而实现桌宠机械动作和 OLED 表情之间的联动。

OLED 采用缓冲区刷新方式，并对电压显示刷新频率进行限制，避免频繁刷新屏幕影响其他任务运行。

---

## 8. 电池电压采集

电池电压通过：

ADC1_IN4 + DMA1_Channel1

进行采集。

ADC 工作于连续转换模式，DMA 循环将最新 ADC 数据自动搬运到内存中，CPU 不需要持续轮询 ADC。

数据处理流程：

电池电压
→ 电阻分压
→ ADC1_IN4
→ ADC 转换
→ DMA 自动搬运
→ 一阶低通滤波
→ 电压换算
→ OLED 显示

电池端采用 1/4 分压，软件中根据：

Vbat = ADC / 4095 × 3.3 × 4

还原实际电池电压。

为减小 ADC 波动对 OLED 显示的影响，对采样结果加入一阶低通滤波。

---

## 9. 呼吸灯控制

使用 TIM3 CH3 / CH4 输出 PWM 控制两路 LED。

通过周期改变 CCR 值实现：

亮度逐渐增加
→ 达到最大亮度
→ 亮度逐渐降低
→ 循环

同时支持：

- 呼吸模式
- 常亮
- 关闭

呼吸灯和舵机运动共用定时器资源，通过不同定时器通道完成输出。

## 软件架构

项目软件主要分为以下几层：

### 应用 / 动作层

- `User/main.c`
- `Hardware/PetAction.c`
- `Hardware/Action.c`

负责命令处理、动作选择、表情联动和动作关键帧编排。

### 舵机控制层

- `Hardware/Servo.c`

负责：

- 当前角度 / 目标角度管理
- 舵机平滑轨迹
- 动作完成判断
- 舵机方向镜像
- 角度偏置
- 机械限幅

### 功能模块

- `Hardware/AD.c`
- `Hardware/BreathLED.c`
- `Hardware/OLED_Data.c`

负责电池采样、呼吸灯和 OLED 表情资源。

### 驱动层

- `Hardware/PWM.c`
- `Hardware/Serial.c`
- `Hardware/BlueTooth.c`
- `Hardware/OLED.c`
- `Hardware/Time4.c`

负责 PWM、UART、定时器、GPIO、ADC/DMA 和软件 I2C 等底层外设。
